# 3인 플레이테스트 운영 규칙

이 문서는 룰북 v0.4의 원문을 변경하지 않고, GM·신·신관 3인이 사용하는 첫 구현의 운영 방식과 임시 수치를 설명합니다.

## 역할과 정보

| 역할 | 주요 권한 | 관찰 범위 |
| --- | --- | --- |
| GM | 판정, 세계 서술, 시간 진행, 지형·자원·부족 수치 편집, 기술 기록, 자리 해제 | 전체 지도·캐릭터·비공개 기록 |
| 신 | 신 생성, 시작 부족 선택, 권능 제안, 대화, D100 | 시작 후보 부족 주변, 선택 부족 주변, GM이 공개한 지역 |
| 신관 | 부족 종족으로 캐릭터 생성, 인접 육상 탐험, 노동 배치, 행동 제안, 대화, D100 | 시작 정착지 주변, 직접 탐험한 지역, GM이 공개한 지역 |

GM은 별도의 세 번째 진행자입니다. 룰북의 두 플레이어 역할은 유지합니다. 플레이어가 발견한 지도는 다른 플레이어에게 자동 공유되지 않습니다. 현재 관찰 중인 정착지·신관 주변 외의 타일은 마지막 관찰 상태를 유지합니다. 타일 발견 시점이 오래되면 화면에 표시합니다.

전체 채팅 외에 수신 역할을 지정할 수 있습니다. GM은 진행을 위해 모든 비공개 메시지와 행동을 열람합니다. 행동 제안과 판정은 요청한 플레이어와 GM에게만 보이며, 정보 전달이 필요하면 대화나 계시로 명시합니다.

## 진행과 판정

1. GM의 방 생성 시 부족·인구·정착지·동물·자원이 먼저 생성됩니다.
2. 신은 신성 레벨 1·신앙 10·소영역 1개로 시작합니다. 부족 선택은 한 번만 가능하며 선택만으로 자동 개종하지 않습니다.
3. 신관은 선택 부족의 구성 종족 중에서 생성합니다. 기존 신관의 종족은 인구 구성 변경으로 바뀌지 않습니다. 힘·지능·사회성의 합계는 100이어야 합니다.
4. 신의 권능 및 신관의 자유 행동은 GM에게 제안합니다. GM이 실행 가능성과 신앙 비용을 판정합니다.
5. 승인된 신의 행동은 지정된 신앙을 한 번 차감합니다. 환경 변화와 발견은 GM이 별도 도구로 적용합니다. 예를 들어 곤충 기적을 승인한 후 식물 자원량을 줄이면 다음 월말 동물 이동의 서식 적합도에 반영됩니다. 비용은 GM이 실제 환경 변화의 규모로 판단합니다.
6. D100은 서버에서 생성합니다. 신성 보정은 서버에서 각 능력치에 `200 × n`을 더합니다. 불가능한 신체적 격차의 판정은 GM이 먼저 수행해야 합니다.
7. 일반 인접 육상 이동은 신관 화면에서 처리합니다. 이동 속도·시간·수역과 산 통과는 GM이 판정하고 시간을 진행합니다.

## 저장된 세계 이어하기

메인 화면의 **저장된 게임 이어하기**를 누르면 이 브라우저에 접속 정보가 남아 있는 세계를 최대 30개까지 선택할 수 있습니다. 역할별 기록은 따로 표시하여 같은 방의 GM·신·신관 접속을 구분합니다. 선택한 세계의 게임 날짜·마지막 자동 저장 시각·지도 크기를 확인하고 **선택한 세계 이어하기**로 접속합니다.

목록을 열 때 각 역할의 접속 키로 서버의 최신 요약 정보를 확인합니다. 인증되지 않은 전체 방 목록은 공개하지 않습니다. 저장본이 없거나 역할 권한이 바뀌면 사유와 JSON 복원·재초대 안내를 표시하며 기록을 자동 삭제하지 않습니다. 예전 브라우저 접속 기록도 그대로 지원합니다.

다른 주소나 브라우저에는 접속 정보가 자동 이전되지 않습니다. 이때는 새 초대 링크나 기록 JSON 불러오기를 사용하세요.

## 기록 내보내기와 불러오기

GM은 연대기의 **기록 JSON 내보내기**로 전체 캠페인을 파일로 보관할 수 있습니다. 시작 화면의 **기록 불러오기**에서 이 파일과 새 GM 이름을 입력하면 새 방으로 복원됩니다. 기존 버전의 내보내기 파일도 지원하며 최대 8MB입니다.

지도 크기·지형·부족·캐릭터·기술·역할별 발견·대화·판정·대기 행동·게임 시간을 유지합니다. 22 × 14 지도를 불러와도 확대하거나 새로 생성하지 않습니다. 파일이 잘못되면 새 방을 만들지 않고 오류를 표시하며, 기존 방은 변경하지 않습니다.

복원한 방은 새 방 코드·GM 접속 키·초대 링크를 사용합니다. 캐릭터는 유지하지만 신·신관 접속 자리는 비웁니다. 두 플레이어는 새 초대 링크로 다시 참여합니다. 내보내기 파일에 접속 비밀키는 없으며, GM 비공개 정보는 포함되어 있으므로 파일은 GM이 보관하세요. 파일을 가진 사람이 별도 복제 방의 GM으로 복원할 수 있습니다.

## 지도 규모와 탐험

새 방은 60 × 38, 총 2,280타일로 생성합니다. 문명 VI 표준 크기(84 × 54, 4,536타일)의 타일 수 약 절반을 기준으로 한 크기이며, 기존 22 × 14보다 약 7.4배 넓습니다. 타일 한 변은 2km를 유지하고 부족은 17종족 후보 중 중복 없이 4개를 추첨하고, 종족별 선호 지형과 시작 거리 기준에 따라 배치합니다. 지형·후보 목록·추첨·배치 기준은 [지형·부족 생성 규칙](world-generation.md)을 따릅니다.

기존 방은 저장된 지도 크기와 지형·캐릭터·발견 정보를 유지합니다. 이동, 동서 경계 연결, 관찰, 생산과 동물 이동은 해당 방의 실제 가로·세로 크기를 사용합니다. 큰 지도를 이용하려면 새 방을 만드세요.

지도에 크기와 타일 수를 표시합니다. 최대 8배까지 확대하고 확대 상태에서 마우스 또는 터치 드래그로 이동할 수 있습니다. 지도 초기화는 전체 지도를 다시 보여줍니다.

지도에서 강은 높은 지대에서 낮은 지대로 육각 타일 옆면을 따라 이어집니다. 기존 세계의 끊어진 강은 GM이 지도 아래 **강줄기 다시 생성**을 실행해 보정할 수 있습니다. 지형·부족·진행 기록은 유지하며 강·범람원과 관련 농경 한도가 갱신됩니다.

## 수면 이동 판정

해안·해양·호수에 들어가거나 나오는 이동은 GM이 판정합니다. 기술명으로 자동 허용하지 않고, **기술의 씨앗에 기록된 수면 이동 기술**과 실제 준비 상태를 근거로 삼습니다.

1. 신관이 행동 제안으로 목적지와 이동 수단을 설명합니다.
2. GM은 기술의 씨앗에서 항해·조선 등 관련 기술과 발전 단계를 확인합니다. 미발견 기술은 근거로 선택할 수 없습니다. 발견·실험 단계는 시험선이나 장비가 실제로 준비되어 있는지 확인하고, 실용화·보급 단계도 항로에 적합한지 판단합니다.
3. GM은 선박·탑승 인원·보급·날씨·연안 또는 원양 여부를 확인합니다. 실행 불가능하면 반려하고, 안전한 이동은 승인하며, 위험하면 기존 D100 도구로 판정합니다. 능력치와 상대 난이도, 실패 결과는 굴리기 전에 합의합니다. 고정 항해 난이도·속도는 아직 정하지 않았습니다.
4. 성공하면 GM이 지도에서 신관에 인접한 목적지를 선택하고 **신관 이동 판정**을 엽니다. 근거 기술과 승인 이유를 기록해 위치를 적용합니다. 신관 주변 발견 정보가 갱신되며, 신의 시야는 자동 공유되지 않습니다. 여러 타일은 한 칸씩 판정합니다.
5. 실패·반려는 위치를 변경하지 않고 행동 판정이나 서술에 기록합니다. 소요 시간은 GM이 별도로 진행합니다. 행동 제안의 승인만으로는 위치가 바뀌지 않습니다.

### 시각 기술 트리와 해금

문명 VI의 기술 명칭과 시대별 발전 흐름에서 착안한 **67개 기술의 TRPG용 재구성**입니다. 원작의 전체 선행 관계·연구 비용·유레카·효과를 그대로 복제한 데이터는 아닙니다. 설명은 이 게임의 GM 판정에 맞게 작성했으며, 선행 관계는 연구 방향을 안내합니다. 원작의 이미지나 아이콘은 사용하지 않습니다.

문명 관리의 **기술의 씨앗**에서 선행 관계를 연결선으로 확인합니다. 카드에 커서를 올리거나 키보드로 초점을 맞추면 설명과 선행 기술이 표시됩니다. 모바일에서는 카드를 눌러 설명을 열 수 있으며 트리는 가로·세로 스크롤됩니다.

- GM은 전체 트리를 보고, 카드를 눌러 발전 단계를 기록합니다. 기술 기록에서 목록을 선택하거나 독자 기술명을 입력할 수도 있습니다.
- **해금은 발견 이상(발견·실험·실용화·보급)**을 뜻합니다. 신과 신관은 선택 부족의 해금된 기술만 보고, 두 끝이 모두 해금된 연결선만 봅니다.
- 미발견 기술의 이름·설명·선행 관계는 플레이어 상태 응답과 SSE에 포함하지 않습니다. 전체 목록은 클라이언트 정적 파일로 배포하지 않습니다. 미발견 상태의 기술 기록 알림은 GM에게만 표시합니다.
- 기술 단계가 미발견으로 돌아가면 플레이어 트리에서도 사라집니다. 이미 공개된 과거 기록이나 플레이어의 기억까지 지우지는 않습니다.
- 선행 기술만 갖췄다고 자동 해금되지 않습니다. GM이 연구·실험·전승 상황을 판정해 기록합니다. 기술 효과나 생산량 변화는 자동 적용되지 않습니다.

수면 이동 계통은 **항해 → 조선 → 지도 제작 → 가로돛**으로 이어집니다. 기술 단계와 실제 선박·항로를 확인한 GM이 이동을 판정하는 원칙을 유지합니다. 독자 기술은 별도 연결선이 없는 자유 기술로 표시합니다.

## 정착지와 인구 — 제9장 구현

GM은 문명 관리에서 선택 부족의 종족별 인구와 정착지별 종족 배분을 기록합니다. 부족 총인구 = 종족별 합계 = 정착지별 합계이며, 각 종족의 배분 합계도 같아야 합니다. 출생은 [인구 특성 v0.3](demography.md)에 따라 월말 계산합니다. 자연사·성숙은 월말 계산하며 전쟁·기근 등 외부 사망·이주는 GM이 판단해 기록합니다. 노동자보다 적은 총인구는 저장할 수 없고 감소한 총인구를 넘는 신도 수는 조정합니다.

월간 식량 소비는 각 종족의 `인구 × 1인 소비량` 합계입니다. 소비량 0·15·30·60은 규칙을 따르고, 종족별 배정은 기존 임시안을 기본값으로 제시합니다. 일반 NPC는 총인구로 처리합니다. 주요 NPC는 이름·종족·역할·소속 정착지·설명을 개별 기록하며, 인구를 추가로 생성하지 않습니다. 설명은 해당 부족의 신·신관도 열람하므로 GM 비밀은 넣지 않습니다.

### 정착지 단계와 밀집도

| 단계 | 종류 | 수용 인구 기준안 |
| --- | --- | --- |
| 0 | 야영지 | 10~50명 |
| 1 | 촌락 | 50~300명 |
| 2 | 마을 | 300~1,000명 |
| 3 | 소도시 | 1,000~5,000명 |
| 4 | 도시 | 5,000~20,000명 |
| 5 | 대도시 | 20,000~50,000명 |

범위와 밀집도 4단계(낮음·보통·높음·초고밀도)는 기준안입니다. 기존 단일 정착지는 초기 표시를 인구에 맞게 제안하고, 이후 단계는 GM이 변경합니다. 기준 범위를 강제 제한하거나 인구 변화만으로 자동 승급하지 않습니다. 50·300·1,000·5,000·20,000명 경계에서는 초기 참고 단계를 상위 단계로 제안합니다.

### 인접 확장과 도시권

GM은 기존 정착지에 인접한 빈 육상 타일에 정착지를 세웁니다. 수역·산·이미 정착지가 있는 타일은 선택할 수 없습니다. 출발 정착지의 구성 종족과 이주 인구를 정하며, 해당 종족 인원을 출발지에서 빼고 새 정착지에 옮깁니다. 부족 총인구와 종족별 총인원은 바뀌지 않습니다. 복합 이주나 이후 주민 재배치는 종족별 인구 관리의 정착지 배분에서 기록합니다.

같은 부족의 인접 정착지를 도시권으로 연결하거나 연결을 해제할 수 있습니다. 연결된 정착지를 묶어 도시권과 합산 인구를 표시합니다. 연결 자체는 생산량을 늘리지 않습니다. 생산권은 모든 정착지의 타일과 인접 6타일의 합집합이며, 부족 노동력을 한 번만 적용하고 겹친 타일 한도·자원을 공유합니다.

### 주거·시설과 자연 공간 — 시험 계산

GM이 각 정착지 타일의 주거·시설 점유율 0~100%를 평가해 입력합니다. 밀집도 단계로 점유율을 자동 결정하지 않습니다. 시험 계산은 `이용 가능한 비율 = 1 - 점유율/100`이며 육상 생산 한도에 곱합니다. 점유율 증가 시 동물·식물 잔량을 남은 공간 비율만큼 줄이고, 월말 자연 회복도 기존 수용 한도에 남은 공간 비율을 적용합니다. 점유율 감소만으로 사라진 자원이 즉시 복원되지는 않습니다. 해양 어업 한도에는 이 육상 점유율 계산을 적용하지 않습니다.

정착지 정치·인구 정보는 소속 플레이어에게 보이지만, 멀리 있는 타일 환경은 기존 관찰 규칙을 따릅니다. 기존 저장본은 단일 종족·본거지 정착지로 읽으며 기존 지형·식량·인구를 바꾸지 않습니다. 새 필드는 내보내기·불러오기에서 보존하고 검증합니다.

## 인구 정산 — v0.3 시험 규칙

[17종족 인구 특성과 운영 규칙](demography.md)을 사용합니다. 생식능력·성숙 나이·평균 수명은 각각 독립된 고유값입니다. 인간 기준 월 출생률 0.2%를 **성숙 인구 × 번식 참여율**에 적용하며, 소수 누적을 저장합니다. 신생아는 출생 월부터 해당 종족의 성숙 나이에 도달할 때까지 노동·출생 계산에서 제외합니다.

자연사는 평균 수명과 연령을 사용하는 별도 Weibull 시험 모형으로 처리합니다. 평균 수명에 도달하면 확정 사망하는 방식이 아닙니다. 출생 환경 배율·번식 참여율·자연사 환경 배율·별도 주거 한도는 GM이 독립적으로 조절합니다. 자연사·성숙 이후 출생을 처리하며, 초과 노동 배치는 성숙 인구에 맞춰 줄입니다. 일자리를 자동으로 늘리지는 않습니다.

GM은 연령 분포 관리에서 정착지·종족별 연령 인원을 기록합니다. 이주나 인구 재배분에도 출생 월을 보존합니다. 연령이 없던 기존 주민은 성숙 시점의 성체로 해석하고 과거 자연사를 소급하지 않습니다. 전쟁·기근 등 외부 사망과 개인 캐릭터의 생사는 GM이 관리합니다.

## 월말 정산

시험판에서 1개월은 30일입니다. GM이 시간·일·주·월 중 하나를 선택하여 시간을 진행하며, 월 경계를 넘을 때마다 해당 정산을 한 번씩 처리합니다. 자동 현실 시간은 사용하지 않습니다.

1. 정착지와 인접 6타일에서 노동자 수 × 생산량, 지형 생산 한도, 자연자원 잔량 중 가능한 만큼 생산합니다.
2. 겹치는 생산권은 타일별 생산 한도와 자연자원을 공유합니다. 현재 시험판은 생성된 부족의 순서로 배분하며, 공평 배분 알고리즘은 아직 없습니다.
3. 종족별 소비량 × 인구를 모두 합산해 식량을 사용합니다. 소비 순서는 과일 → 고기 → 곡물이라는 시험판 편의 규칙입니다.
4. 식량 부족은 기록하지만 기아 사망은 자동 적용하지 않습니다. 연령에 따른 자연사는 별도로 처리합니다.
5. 선택 부족의 신도 수 × 0.5만큼 신앙을 더합니다. 감동 보너스·제단 효과는 GM이 별도로 판정하여 조정합니다.
6. 동물 개체군 일부가 인접한 적합 서식지로 이동합니다. 수역·육지는 분리하며 식물 자원, 강, 숲, 계절의 영향을 반영합니다. 실제 개체군 수를 원래 타일에서 빼고 도착 타일에 더합니다. 이어서 자연 회복과 시험용 수용 한도를 적용합니다. 포식자와 상세 종별 생태는 아직 모델링하지 않습니다.
7. 각 부족에 대해 서버 D100을 한 번 굴립니다. 시험 확률을 통과하면 사건 후보를 기록하며 효과는 GM이 결정합니다. 선택 부족 외의 사건·정산은 GM에게만 공개합니다.
