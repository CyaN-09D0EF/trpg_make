# 신들의 문명 TRPG

GM 1명, 신 플레이어 1명, 신관 플레이어 1명이 함께하는 브라우저 기반 협동 문명 육성 게임입니다. 세계 지도, 역할별 비공개 정보, 실시간 대화와 GM 판정을 갖춘 플레이테스트 버전입니다.

현재 게임 규칙의 기준본은 [통합 룰북 v0.4](docs/rulebook.md)입니다.
이후 규칙 변경은 기준본의 해당 항목에 반영하며, 확정 규칙과 시험용·미확정 수치를 구분합니다.

## 실행

Node.js 22 이상이 필요합니다. 게임 서버와 화면에는 외부 런타임 의존성이 없어 별도 패키지 설치나 빌드 없이 실행할 수 있습니다.

```sh
cd /workspace/trpg_make
npm start
```

기본 접속 포트는 `3000`이며 기본 바인딩은 `0.0.0.0`입니다. 브라우저에서 서버 주소의 해당 포트로 접속합니다. 실행 중인 서버가 있어야 세 플레이어가 같은 방을 이용할 수 있습니다.

```sh
PORT=3000 HOST=0.0.0.0 DATA_DIR=/workspace/trpg_make/data npm start
```

다른 컴퓨터에서 함께하려면 접속 가능한 서버에 실행하고 방에서 만든 초대 링크를 공유하세요. 인터넷 공개 배포는 이 저장소 생성만으로 이루어지지 않습니다. 원격 서비스에는 HTTPS와 영속 디스크를 사용하고, 프록시는 `/api/rooms/*/events`의 SSE 응답을 버퍼링하지 않도록 설정하세요. 방 생성·참여 외의 API는 역할별 접속 키로 인증합니다.

## 첫 플레이

1. GM이 **새로운 세계 만들기**에서 방 이름과 GM 이름을 입력합니다. 시드는 선택 사항입니다.
2. **플레이어 초대**에서 신·신관 링크를 각각 전달합니다. 각자 링크를 열어 역할과 이름으로 참여합니다. 한 브라우저의 다른 탭으로도 역할별 시험이 가능합니다.
3. 신은 이름·외형·성향·소영역 하나를 정하고, 이미 생성된 네 부족 중 시작 부족을 선택합니다.
4. 신관은 해당 부족의 종족으로 이름을 정하고 힘·지능·사회성에 합계 100포인트를 배분합니다.
5. 플레이어는 탐험·노동 배치·행동 제안을 하고, GM은 행동 판정·서술·정보 공개·수치와 지형 조정·시간 진행을 담당합니다.

**신의 권능과 신관의 자유 행동은 제안 → GM 판정으로 진행**합니다. 승인 시 신앙 비용은 차감되며, 지형·자원·식량 등 실제 변화는 GM 도구로 적용합니다. 서버 D100 판정은 `A / (A + B)`와 신성 보정 `200 × n`을 사용합니다. 전투 결과, 기적의 범위, 연구 조건 등은 룰북에 따라 GM이 결정합니다.

## 구현된 기능

- 역할마다 한 자리씩 참여, 접속 표시, 초대 링크, GM 자리 해제와 재초대.
- 시드 기반 22 × 14 육각 지도, 동서 연결, 타일 경계의 강, 지형·고도·특성·자원·유적·부족 생성.
- GM 전지 시야, 신·신관의 독립된 관찰 기록. 미발견 타일은 서버 응답에서 제외하며 오래된 발견 정보는 별도 시점으로 보관.
- 신 생성, 시작 부족 선택, 종족이 고정된 신관 생성, 인접 지상 타일 탐험.
- 전체 대화·역할별 비공개 대화와 서술, 비공개 행동 제안, GM 승인·반려, 서버 D100.
- 부족 식량 3종과 노동자 배치, 7타일 생산권, 공유되는 생산 한도·자연자원, 월말 생산·소비와 신앙 정산.
- 시간·일·주·월 진행, 월간 부족별 D100 사건 후보, 자원 회복과 서식 적합도를 고려한 동물 이동.
- GM 타일 환경 편집, 신앙·신도·인구·식량 조정, 67개 기술의 시각 트리와 설명 툴팁, GM 기술 단계 기록·역할별 해금 공개.
- 방마다 자동 저장·재접속·서버 재시작 복원, 비밀키를 제외한 JSON 기록 내보내기, 모바일 화면.

## 시험 수치와 범위

룰북 원문은 수정하지 않았습니다. 3인 운영 방식과 자동화 범위는 [플레이테스트 운영 규칙](docs/playtest.md)에 따로 기록했습니다.

월간 소비 `15·30·60`과 신도별 기본 신앙 `0.5`는 확정 규칙을 따릅니다. **노동자 생산량 75, 지형 한도 배율 4, 자원 회복 계수 0.2, 월간 사건 확률 25%는 이 버전의 시험 기본값**이며 GM이 변경할 수 있습니다. 종족별 소비 단계는 원문의 임시 배정을 사용합니다. 생산량과 인구 소비량의 균형은 실제 플레이를 통해 추가 조정해야 합니다.

목축·건축·제단 생산·인구 증감·직업/스킬 경험치·흉물 성장·전투 피해·신성 성장은 자동화하지 않았으며 GM 서술과 판정으로 진행합니다. 사건 카드는 환경에 맞춘 정식 카드 체계가 아닌 GM용 후보입니다. 해상·산악 이동도 GM 판정 대상입니다.

## 저장과 복원

- `data/<방 코드>.json`에 세계·캐릭터·대화·역할별 발견·접속 키 해시를 원자적으로 저장합니다. 변경 요청은 방별로 직렬화됩니다.
- 서버를 같은 `DATA_DIR`로 다시 실행하면 방이 복원됩니다. 브라우저의 **이어 쓰는 연대기**에서 접속할 수 있습니다.
- 접속 키는 각 브라우저의 로컬 저장소에 있으므로, 브라우저 데이터를 지우면 GM이 자리를 해제하고 재초대해야 합니다. GM의 접속 정보는 보관해야 합니다.
- 서버를 중지한 뒤 `data` 폴더 전체를 별도 보관하면 운영 백업으로 사용할 수 있습니다. GM의 **기록 JSON 내보내기**는 비밀키가 없는 열람용 기록이며 복원용 백업이 아닙니다.
- 대화·사건 기록은 방별 최근 500개, 행동 요청은 최근 처리 내역 약 160개와 대기 중인 요청을 유지합니다. 영구 보존이 필요하면 주기적으로 내보내세요.

## 개발과 검증

```sh
npm ci --cache /workspace/.cache/npm
npm test
npm run test:browser
```

`npm test`는 게임 규칙과 실제 HTTP/SSE 서버를 검사합니다. `npm run test:browser`는 서로 다른 브라우저 컨텍스트 3개에서 생성·참여·비공개 채팅·행동 판정·정산·재접속·모바일 화면을 검사합니다. 이 환경에 설치된 `/usr/bin/chromium`을 사용하며, 다른 환경에서는 `CHROMIUM_PATH`로 Chromium 경로를 지정하거나 Playwright의 Chromium을 설치할 수 있습니다. 스크린샷과 실패 진단은 무시되는 `test-results/`에 생성됩니다.

```sh
npm run dev
```

서버는 Node 기본 HTTP와 SSE, 화면은 의존성 없는 HTML/CSS/JavaScript입니다. 게임 규칙(`lib/game.mjs`)과 세계 생성(`lib/world.mjs`)을 서버·화면에서 분리하여 이후 다른 클라이언트로 확장할 수 있습니다. 이 클라우드 작업은 이미 격리되어 있으므로 별도 Git worktree를 만들 필요가 없습니다.
